## 辅助示例：

1. 处理版本：切换分支比对(分布式软总线为例)，整体信息统计，切分补丁/阅读补丁/内容查找(更改确认)

## 设计层面：

1. 内容：整体原理/运行环境/组件切分(接口位置/内部机理/使用方法)，融入全阶段(配合实现层面和调试层面的推进)
2. 方法：顺序是上(需求/使用)/中(设计/发布)下(编译/测试)，文档处理(设计/编译/使用)/AI辅助/源码阅读
3. 难点：很难做到知行合一，尤其是在缺少设计文档时，在源码阅读阶段，很难边阅读边形成整体框架结构。

## 实现层面：

1. 内容：具体点的原理（源码/编译/运行），融入全阶段(配合设计层面和调试层面的推进)
2. 方法：顺序是设计先行/源码阅读跟进/调试分析辅助/设计再行，文档处理(原理/使用/定制)/版本补丁/辅助工具
3. 难点：熟练高效地操作各类工具来处理大量代码，需要足够地积累和耐心。做到设计先行(高效地在设计和实现之间进行切换)

## 调试层面：

1. 内容：具体问题确认/找到原因(能够支撑解决方案)/给出解决方案；融入全阶段(配合实现层面和设计层面的推进)。
2. 方法：顺序是缩范围/找原因/给方案；文档处理(复现流程/数据细节/原理整理)/比对分析(代码定制/版本补丁/工具处理)/AI辅助
3. 难点：复现问题/对应汇编和源码/熟悉运行时环境；直接原因和根本原因的切换(单元测试)/方案和原因间的平衡切换/沟通协调

## 辅助示例：

1. 内容概述：熟悉环境(参见运行时监控)，处理版本/细化调试/阅读代码
2. 处理版本：切换分支比对(分布式软总线为例)，整体信息统计，切分补丁/阅读补丁/内容查找(更改确认)
3. 细化调试：汇编和源码对应；配合设计和实现的运行时数据流程确认；运行时实际加载(尤其是瞬间处理并释放资源/firefox)
4. 阅读代码：整体源码阅读(flatpak为例), 辅助工具/作者思路/整体整理；多窗口操作/针对性阅读(具体接口/数据结构/处理流程)
